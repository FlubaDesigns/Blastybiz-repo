# BlastyBiz — Bug Fix Audit Log

| Date | File(s) | What was wrong | How it was fixed |
|------|---------|----------------|-----------------|
| 2026-07-18 | functions/index.js | `businessCreatedTrigger` sent the same generic "Welcome to BlastyBiz" email to every new user regardless of plan. Pro and Agency users got a plain free-tier welcome with no mention of what they paid for. Admin alert also omitted plan. | Rewrote `businessCreatedTrigger` to read `userData.plan` and branch into three paths: Agency → `agency-welcome` template + agency-specific fallback HTML (unlimited clients, full power); Pro → `pro-welcome` template + pro-specific fallback HTML (full API, scheduled posts); Starter → `welcome` template + free fallback HTML with upgrade nudge link. Template type lookup checks Firestore `emailTemplates` for each type before falling back to hardcoded HTML. Admin alert subject now includes plan tier. |
| 2026-07-18 | BlastyBiz-Login.html, BlastyBiz-Dashboard.html | (1) New paid-plan users were sent to Chat-Onboarding instead of Square checkout. `afterAuth()` checked `onboarded` and `businesses` first — a brand-new user has neither, so the paid plan stored in localStorage was ignored and they hit the onboarding wizard instead of paying. (2) After email/password signup, the "Check Your Inbox" verify screen appeared below the fold on mobile (below the OR divider and social buttons) with no scroll, so users never saw it. | (1) `afterAuth()` now checks `bb_selected_plan` first — if pro/agency, it skips all onboarding checks and goes straight to `BlastyBiz-Dashboard.html?checkout=plan`. After Square payment (`?success=1`), Dashboard checks if user is not onboarded and has no businesses; if so, redirects to Chat-Onboarding after 1.8 s. (2) `showVerifyView()` now adds `verify-mode` to `#auth-card-wrap`, which via CSS hides the tabs, all auth forms, and the back-home link, leaving only the verify screen visible. `backFromVerify()` removes the class to restore the full form. `window.scrollTo(0)` fires on show so mobile users see the verify screen immediately at the top. |
| 2026-07-18 | BlastyBiz.html, global-style.css | Blast-creation flow used a flat two-step show/hide approach (create-step-1 / create-step-2) with no visual progress, and forced five repeated "About You in Copy" Yes/No decisions on every blast. | Rebuilt the Create tab as a 3-slide wizard (Stage 1 of spec). Added progress bar, step dots, step labels. Slide 1 = Campaign + Blast Info + Extra Facts. Slide 2 = Photos (own step). Slide 3 = Platforms + Generate (unchanged logic). Collapsed the five YN rows behind a single "Edit what appears in this blast" accordion — defaults come from profile, user can override per-blast. Removed dead `step2-back` and `about-you-card` CSS. Bumped global-style.css to v=59. |
| 2026-07-18 | BlastyBiz.html | Stage 1 wizard was 3 slides; platform selection and AI generation were combined in one slide; no per-platform copy review step existed. | Stage 2 (Steps 3–5): Expanded wizard from 3 to 5 slides. Slide 3 = Platform Selection (clean toggle rows via `renderStep3Platforms()`). Slide 4 = AI Generation (Generate button, loading spinner, rewrite/clear, Review Platforms button → Slide 5). Slide 5 = Per-Platform Review (`renderStep5Review()` + `buildStep5Card()`) — one platform at a time with editable copy, Regenerate, Copy, Accept, and Looks Good buttons; sub-progress dots; Final Review button when all platforms reviewed. Added Step 3/5 CSS. Updated `createWizGoTo()`, `createWizNext()`, `CREATE_WIZ_TOTAL=5`, labels. Added `checkS3ContinueBtn()`, `markPlatformReviewed()`, `step5GoTo/Prev/Next()`, `goToFinalReview()`. `renderQuickSelect()` now delegates to `renderStep3Platforms()`. |
| 2026-07-18 | functions/index.js | Full end-to-end test of all 3 wizard stages via live CF calls revealed a critical bug: `adaptListing` CF told the AI to label each platform section as `=== GOOGLE BUSINESS PROFILE ===` with no ID in the header, and the JSON return template said `"PLATFORM_ID": "adapted text"` — so the AI returned keys like `GOOGLE_BUSINESS_PROFILE` instead of `google`. The wizard reads `adaptations[p.id]` (e.g. `adaptations['google']`), so every lookup returned `undefined`. Every single user received blank copy on every generate — content was silently dropped. Same bug existed in `generateScheduledPost` (auto-scheduled posts). | Fixed `buildPlatformBlock()` to include `(json key: "${p.id}")` in every section header so the AI sees the exact key to use. Fixed both prompt templates to dynamically list the actual platform IDs in the example JSON (e.g. `"google": "adapted text for Google Business Profile"`). Deployed `adaptListing` CF. Verified via live test: response now returns `{ adaptations: { google: "...", facebook: "...", nextdoor: "..." } }`. Also fired deploy of `scheduledPostingCheck` to fix the same bug in auto-scheduled posts. |
| 2026-07-18 | BlastyBiz.html | Full-audit of all 3 wizard stages found 2 bugs: (1) `setLocationType()` called `.classList.toggle()` on null — `loc-btn-physical` and `loc-btn-online` IDs were removed from the wizard HTML but not from the JS, causing a TypeError crash on every profile load for online businesses. (2) `renderPlatformHistory()` looked for `platform-history-card` and `platform-history-list` elements that didn't exist anywhere in the HTML, silently returning early and never rendering campaign platform history. | (1) Added `?.` optional chaining to the two null-crashing getElementById lines in `setLocationType()`. (2) Added `<div class="card hidden" id="platform-history-card">` and inner `<div id="platform-history-list">` to Slide 1 inside `campaign-content`, just after the Continue button — hidden by default, shown by `renderPlatformHistory()` when history exists. |
| 2026-07-18 | BlastyBiz-Listing-Preview.html, BlastyBiz.html | Listing-Preview was a desktop-oriented draft-editing page with hardcoded 5 tabs, Auto-Send toggle, Regenerate/Make Shorter buttons, editable headline/CTA fields, and an Approval Flow stepper — all wrong for the final publish step. BlastyBiz.html had ~270 lines of dead code: body of `renderQuickSelect()` after its `return;` early exit, `togglePlatformAccordion()`, `showCopyInAccordions()` (and its call in `runAdaptation`), `saveGsUrl()`, `openGsPage()`. | Stage 3: (1) Rebuilt BlastyBiz-Listing-Preview.html as the mobile-first Step 6 final publish screen — shows Blast Summary, Platforms in this blast (auto vs copy-paste badges), read-only AI copy previews (collapsible per-platform), per-blast scheduling section (labeled "this blast only, separate from auto-post schedule"), Publish Blast button (calls `approveDraft` CF → redirects to Publishing Status), and copy-paste panel for manual platforms. Removed editing UI, Regenerate, Auto-Send toggle, Approval stepper, hardcoded tabs. (2) Removed 267 lines of dead code from BlastyBiz.html: collapsed `renderQuickSelect()` to a 3-line delegate, deleted `togglePlatformAccordion()`, `showCopyInAccordions()`, `saveGsUrl()`, `openGsPage()`, and the corresponding `showCopyInAccordions()` call + `featuredPhotoUrl` variable in `runAdaptation()`. |
