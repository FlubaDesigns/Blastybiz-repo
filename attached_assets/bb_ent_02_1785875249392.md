## 0. RELEASE BLOCKER — `functions/index.js` requires directories that do not exist

**Severity: total deploy failure. Fix before anything else.**

`functions/index.js` lines 32–38:

```js
Object.assign(exports, require('./ai'));
Object.assign(exports, require('./payments'));
Object.assign(exports, require('./oauth'));
Object.assign(exports, require('./publishing'));
Object.assign(exports, require('./admin'));
Object.assign(exports, require('./scheduled'));
Object.assign(exports, require('./user'));
```

Actual layout on disk:

```
functions/
  index.js
  lib/       ← 14 shared helper files
  modules/   ← ai.js  payments.js  oauth.js  publishing.js
               admin.js  scheduled.js  business.js  misc.js
```

There is no `functions/ai/`, no `functions/payments/`, no `functions/oauth/`, no `functions/publishing/`, no `functions/admin/`, no `functions/scheduled/`, and no `functions/user/` under any name.

### Two distinct faults

**Fault 1 — wrong path segment.** Every `require` is missing `./modules/`. Node throws `MODULE_NOT_FOUND` on line 32 before reaching line 33. Because Firebase loads `index.js` to enumerate exports at deploy time, the failure is not scoped to one function — **the entire deploy aborts and all 61 functions fail.** Production keeps running the previously deployed revision, so this presents as "my deploy keeps failing," not as an outage.

**Fault 2 — `./user` does not correspond to any module.** The user-lifecycle code was split into two files that the barrel never names:

| File | Exports |
|---|---|
| `modules/business.js` | `createBusiness`, `deleteBusiness`, **`deleteAccount`**, `sendVerificationEmail` |
| `modules/misc.js` | `sendTestEmail`, `contactForm`, **`unsubscribeEmail`** |

Fixing only Fault 1 still leaves these seven endpoints unexported and silently deleted from the deployment. Two of them matter disproportionately:

- **`deleteAccount`** — the GDPR/CCPA erasure path fixed in Pass 01. Gone.
- **`unsubscribeEmail`** — the CAN-SPAM unsubscribe target. Every unsubscribe link in every email already sent would 404. That is a compliance exposure, not just a broken link.

### Fix — replace lines 32–38 in `functions/index.js`

```js
Object.assign(exports, require('./modules/ai'));
Object.assign(exports, require('./modules/payments'));
Object.assign(exports, require('./modules/oauth'));
Object.assign(exports, require('./modules/publishing'));
Object.assign(exports, require('./modules/admin'));
Object.assign(exports, require('./modules/scheduled'));
Object.assign(exports, require('./modules/business'));
Object.assign(exports, require('./modules/misc'));
```

Seven requires become eight. Do not drop `misc`.

### Also fix the header comment

Lines 7–15 of `index.js` document a layout that does not exist (`ai/`, `payments/`, `user/`, …). It is the reason the requires look plausible on a read-through. Update it to describe `lib/` and `modules/` as they actually are, or the next person — human or agent — will reintroduce the same mistake.

### Verification after the fix

```bash
cd functions && node -e "const e=require('./index.js'); console.log(Object.keys(e).length)"
```

Expect **61**. Any lower number means a module is still unwired. This one command would have caught the whole problem and belongs in `check-release.cjs` (see §3).

### Why this happened, and the systemic lesson

The refactor was correct. The barrel was written against the layout the comment described rather than the layout on disk, and nothing in the toolchain compares the two. This is precisely the failure mode Pass 01 §5.5 predicted: conventions that live in comments rather than in a failing build. An agent doing this refactor had no mechanical signal it had gone wrong, and neither did a human.

## 2. Still open — carried forward

Nothing below is new. All were Pass 01 items scheduled for later phases; this is a status record, not a criticism of sequencing.

### Introduced by the Pass 01 token move — highest priority after §0

**`private/tokens` survives account deletion.** `business.js:120` collects `connsSnap` — the parent `platformConnections` documents — but never enumerates the `private` subcollection beneath each one. Firestore does not cascade-delete subcollections when a parent document is deleted.

Consequence: **every account deletion leaves live OAuth access and refresh tokens behind as orphaned documents.** Same class of failure as the photos bug Pass 01 §1.4 fixed, created by the fix for §1.5.

Fix — inside the `for (const bizDoc of bizSnap.docs)` loop, after `connsSnap` is populated:

```js
for (const connDoc of connsSnap.docs) {
  const privSnap = await connDoc.ref.collection('private').get();
  privSnap.docs.forEach(d => bizSubRefs.push(d.ref));
}
```

Then run a one-time sweep for accounts already deleted since the token move — those documents are in Firestore right now.

## 3. What §0 says about the release process

The barrel bug is worth more than its fix, because of what it reveals.

It was undetectable by reading the diff — the requires look correct in isolation, and the header comment actively confirms them. It would not have survived a single execution. Nothing in the pipeline executes anything, because there is no pipeline.

`check-release.cjs` exists, is pointed at a path that does not exist, and therefore cannot have run. Had it run and included one line, this would have been caught before the zip was packed:

```js
const exported = Object.keys(require('../functions/index.js')).length;
if (exported < 61) fail(`Barrel exports ${exported} functions, expected 61`);
```

Three checks worth adding alongside it, each of which corresponds to a bug that has actually occurred in this codebase:

1. **Barrel export count** — catches §0.
2. **`innerHTML` + `${` without `escHtml`** — catches Pass 01 §3.1.
3. **Storage-path symmetry** — every prefix written by the client appears in `deleteAccount`; catches Pass 01 §1.4 and, extended to subcollections, the `private/tokens` gap above.

This matters more here than in a typical codebase because of the stated goal of handing operations to AI agents. An agent will not remember that `deleteAccount` must be updated when a new subcollection is added. It will reliably obey a failing build. Every convention currently living in a comment is a bug an agent will eventually write — and in this case, already did.

Repointing `check-release.cjs` at `public/` and wiring it into a GitHub Action is a few hours of work and is the highest-leverage remaining item on the whole list after §0 and the token-deletion gap.

## Closing

Twenty of 47 closed in two passes, including the whole P0 security tranche and the largest maintainability item. The direction is right and the quality of the individual fixes is high — the transactional job claim, the `getPlanConfig` fallback design, and the token subcollection isolation are all done properly rather than patched over.

The one thing to take from this pass beyond the fix list: the codebase has now reached a size where correctness cannot be verified by reading it. §0 proves that — a 38-line file, carefully written, with a bug that takes down all 61 functions and that no amount of re-reading would have surfaced. From here, tests and a build gate are not process hygiene. They are the only remaining way to know whether a change worked.
