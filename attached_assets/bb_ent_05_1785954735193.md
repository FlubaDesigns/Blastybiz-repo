### 1.1 Scheduled posting reconnected ✅

```js
const snap = await db.collectionGroup('listingDrafts')
  .where('schedule.enabled', '==', true)
```

The header comment (lines 113–117) explains why due-ness is evaluated in memory rather than range-filtered in the query: `nextRunAt` is an ISO string nested inside a map, and range-filtering that requires a composite index and is fragile. The reasoning is correct and worth having written down.

## Part 2 — Three items remaining

### 2.1 Seven dead module directories — delete them

**This is Pass 03 §2 recurring, at roughly four times the size.**

`functions/` now contains two parallel implementations of the entire backend:

```
functions/
  index.js          → requires ./modules/*     ← LIVE
  lib/shared.js                                ← LIVE
  modules/          8 files, 3,824 lines       ← LIVE
  ai/               613 lines                  ← DEAD
  payments/         523 lines                  ← DEAD
  oauth/            246 lines                  ← DEAD
  publishing/       542 lines                  ← DEAD
  admin/            510 lines                  ← DEAD
  scheduled/        883 lines                  ← DEAD
  user/             455 lines                  ← DEAD
```

**3,772 lines of dead code**, almost exactly matching the live tree in size.

These are the original refactor attempt — the directories the Pass 02 barrel was written against. Every one of them imports the 13 `lib/` files that were deleted in the Pass 03 Option A cleanup:

| Directory | Broken imports |
|---|---|
| `ai/` | `../lib/ai`, `../lib/auth`, `../lib/db`, `../lib/platforms`, `../lib/rateLimit` |
| `payments/` | `../lib/auth`, `../lib/config`, `../lib/db`, `../lib/email`, `../lib/rateLimit`, `../lib/square` |
| `oauth/` | `../lib/auth`, `../lib/config`, `../lib/db`, `../lib/rateLimit` |
| `publishing/` | `../lib/auth`, `../lib/config`, `../lib/db`, `../lib/email`, `../lib/publishers` |
| `admin/` | 9 files, including `../lib/yelp` |
| `scheduled/` | 8 files, including `../lib/yelp` |
| `user/` | 7 files |

**None of these directories can load.** Every one throws `MODULE_NOT_FOUND` on its first require.

**Why it is not breaking anything today:** `functions/index.js` correctly requires `./modules/*`. The dead directories are never touched at runtime.

**Why it has to go before V1:**

1. **It is a loaded trap.** The barrel bug in Pass 02 happened because `require('./ai')` looked correct. Those directories now *exist*, so the same mistake would resolve to a real path and fail one layer deeper — with a `MODULE_NOT_FOUND` on `../lib/db` instead, which is a much harder thing to diagnose.
2. **It resurrects Yelp.** `admin/index.js:467` and `scheduled/index.js:315` both still declare `secrets: ['YELP_API_KEY']`. Any future work that picks up the wrong tree reintroduces the dependency you just paid to remove.
3. **`scheduled/index.js` is 883 lines against the live 485.** It is nearly twice the size of the file that actually runs. Anyone scanning the directory for "the real scheduling code" will pick the wrong one on size alone.
4. **It deploys.** `.firebaseignore` excludes `node_modules`, `.git`, dotfiles, and `dev-login.html`. It does not exclude these. All 3,772 lines upload on every deploy.

**Fix:**

```bash
rm -rf functions/ai functions/payments functions/oauth \
       functions/publishing functions/admin functions/scheduled functions/user
```

Nothing references them. `index.js` requires `./modules/` explicitly. The deletion is safe.

**Then add the guard to `check-release.cjs`** — this is the third time this exact class of problem has appeared, and it will not be the last without a mechanical check:

```js
// every .js under functions/ must be reachable from index.js
```

### 2.2 Stale header comment

`modules/scheduled.js:3` still lists a function that no longer exists:

```js
/**
 * BlastyBiz — Scheduled Cloud Functions
 * scheduledPostingCheck, scheduledYelpCategoryRefresh, scheduledUpgradeNudge,
 *                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ removed
```

Trivial, but header comments are how the next reader — human or agent — decides what a file contains. A comment that describes a layout or an export list that no longer exists is exactly what caused the Pass 02 barrel bug. Keep them honest or delete them.

### 2.3 `scheduledWeeklyDigest` missing `timeZone`

`modules/scheduled.js:238`:

```js
{ schedule: 'every monday 08:00', region: 'us-central1', secrets: [...] },
```

The other two nudge jobs both carry `timeZone: 'America/New_York'`. This one does not, so Cloud Scheduler defaults to UTC — **08:00 UTC is 3:00 AM Eastern.** Your weekly digest lands in customer inboxes in the middle of the night, which is roughly the worst possible send time for open rates.

**Fix:** add `timeZone: 'America/New_York'` to match the sibling jobs.

## Part 4 — Known ceiling, not a blocker

`scheduledPostingCheck` (`scheduled.js:124`) queries:

```js
.where('schedule.enabled', '==', true)
.limit(200)
```

with no cursor, then filters due-ness in memory.

The 200 is a cap on **the total number of drafts with scheduling enabled**, not the number due at that moment. Past 200, the query returns the same first 200 documents every hour and the remainder are never processed — silently, with no error and no log line.

At launch scale this is irrelevant. It becomes a live incident somewhere north of 200 scheduled drafts across all customers, and the symptom will be "some customers' posts stopped going out" with nothing in the logs to explain it.

**Not a V1 blocker.** But add a `startAfter` cursor loop before you are anywhere near that number, and consider a log line when `snap.size === 200` so the ceiling announces itself instead of failing quietly.

## Closing

Five passes, 47 items opened, and V1 arrives with three mechanical cleanups outstanding. The security posture bears no resemblance to where this started — the unauthenticated AI endpoint, the browser-readable OAuth tokens, the browser-writable Secret Manager path, the erasure gaps, and the duplicate-post race are all closed and verified closed.

The Yelp resolution is worth calling out as the best single piece of work in the sequence. The instruction was "remove it." What came back was a manual category upload endpoint, generalized to any platform, with backward-compatible mirroring so nothing reading the old collection breaks. That is understanding the requirement rather than executing the ticket, and it removed a $229/month line item permanently.

The one thing that has not changed across five passes is the verification gap. Item 2.1 in this document is the third appearance of the same pattern — a parallel copy of the codebase that looks canonical and is not — and each recurrence has been larger than the last: one file, then thirteen, now seven directories and 3,772 lines. It has never caused an outage because it has been caught each time by reading. That is not a durable control, and reading is an expensive way to buy it.

Ship V1. Then build the smoke test, before the fourth recurrence is the one nobody catches.
