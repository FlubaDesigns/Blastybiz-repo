🔗 Planned Platform APIs To Build
💼 LinkedIn Posts API
Upgrade LinkedIn from copy-paste to auto-post
▼

LinkedIn has a full Posts API and allows third-party apps to post on behalf of business pages. Implementation steps:

  • Create a LinkedIn App — go to linkedin.com/developers/apps, create an app, and request the w_member_social and r_basicprofile OAuth scopes.
  • Get LinkedIn Page Access — request the w_organization_social scope for posting to Company Pages (not just personal profiles). This requires a company page to be linked to your app.
  • Add OAuth Connect flow — follow the same pattern used for Google/Facebook in artifacts/api-server/public/connect.html. LinkedIn uses standard OAuth 2.0 with auth code + token exchange.
  • Store tokens in Firestore — save accessToken, refreshToken, expiresAt, and linkedinOrgId (the company page URN) in the user's platformConnections/linkedin doc.
  • Add Cloud Function: postToLinkedIn — call the LinkedIn Posts API endpoint POST https://api.linkedin.com/v2/ugcPosts with the org URN and the AI-generated content. LinkedIn tokens expire in 60 days — implement token refresh.
  • Switch platform type to api — update the linkedin entry in BlastyBiz.html platforms array and SCHED_PLATFORMS in functions/index.js.

Note: LinkedIn's API does not require an app review process like Meta — you can go live once your app is approved (usually same day). Token lifespan is 60 days; plan for refresh logic.

✖️ X (Twitter) Posts API
Upgrade X from copy-paste to auto-post — requires per-user developer accounts
▼

X has a working Posts API but the auth model is different — each business user must have their own X Developer account. Steps:

  • Understand the constraint — X does not allow a single app to post to unlimited third-party accounts without each user having a developer account or going through the Elevated API tier. Free tier: 1,500 posts/month per app. This is fine for BlastyBiz at current scale.
  • Create an X Developer App — go to developer.x.com, create a project + app, and enable OAuth 2.0 with PKCE. Request tweet.write and users.read scopes.
  • Add OAuth Connect flow — add X to connect.html with the same OAuth pattern. X uses OAuth 2.0 with PKCE (no client secret needed on the redirect). Store the auth code server-side and exchange for tokens via your Express API.
  • Store tokens in Firestore — save accessToken, refreshToken, expiresAt, and xUserId in the user's platformConnections/x doc.
  • Add Cloud Function: postToX — call POST https://api.twitter.com/2/tweets with the Bearer token and the AI-generated text (max 280 chars). Tokens expire in 2 hours — implement refresh using the refresh token.
  • Switch platform type to api — update the x entry in BlastyBiz.html platforms array and SCHED_PLATFORMS in functions/index.js.

Note: Keep the copy-paste fallback available. If a user does not connect X, the card still generates a 280-char post they can paste manually. X API access at the Basic tier ($100/mo) removes the 1,500-post cap if needed at scale.
